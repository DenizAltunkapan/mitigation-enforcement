# Debian 7 i386 versus Debian 13 amd64 baseline

Labs 01–03 now have a comparison with matching source, Makefiles, collector and
build-variable values. The recovered Debian 7 capture from 26 October 2026 and
the Debian 13 capture from 27 October each contain five binaries with three
runs: **30 standalone runtime transcripts in total**. The modern session adds
one separate GDB run for Lab 02.

The [comparison snapshot](evidence/baseline-comparison-2026-10-27.json) was
generated by `scripts/export-baseline.py` after checking both full captures,
including binaries and disassembly that are omitted from the text snapshot.
The exporter confirmed identical hashes for all three C sources, all three
Makefiles and `capture-baseline.sh`, plus matching `CC`, `CFLAGS` and `LDFLAGS`.

## What is controlled, and what differs

| Property | Legacy VM | Modern VM |
|---|---|---|
| Distribution | Debian 7.11, recovered installation | Debian 13.6 cloud image |
| Architecture / word size | i686 / 32 bits | x86_64 / 64 bits |
| Compiler / target | GCC 4.7.2-5 / i486-linux-gnu | GCC 14.2.0-19 / x86_64-linux-gnu |
| Binutils | 2.22 | 2.44 |
| libc | glibc 2.13 | glibc 2.41 |
| Kernel | 3.2.0-4-686-pae | 6.12.105+deb13-amd64 |
| ASLR setting | 2 | 2 |
| CPU `nx` flag | absent | present |
| User | `lab`, UID 1000 | `lab`, UID 1000 |
| Guest network device | none | none |
| GDB | absent | 16.3 |

Both captures use `CC=gcc`,
`CFLAGS=-O0 -g -Wall -Wextra -fno-omit-frame-pointer` and empty `LDFLAGS`.
The Makefile's compiler probe adds `-no-pie` only where supported, so identical
Makefiles and variables do not imply byte-for-byte identical compiler commands.
Actual build output is preserved for each environment.

This compares two complete environments. It does **not** isolate architecture,
compiler, libc, CPU configuration or kernel effects. Three repeats establish
repeatability for these builds, not ASLR entropy or exploit reliability.

## Lab 01: text placement and randomization

| Observation | Legacy | Modern |
|---|---|---|
| Default ELF type | `EXEC` | `DYN` (PIE) |
| `main`, run 1 | `0x8048688` | `0x56498bad5245` |
| `main`, run 2 | `0x8048688` | `0x55fb26255245` |
| `main`, run 3 | `0x8048688` | `0x56485a26a245` |
| Heap and stack addresses | differ across all three runs | differ across all three runs |
| libc executable mapping start | differs across all three runs | differs across all three runs |

ASLR being enabled does not make a non-PIE executable's text move. The legacy
program's fixed text coexists with changing stack, heap and libc mappings.
On the modern build the PIE executable's text also moves.

The printed `printf from libc` pointer is `0x8048460` in all legacy runs, inside
the executable mapping. In the modern runs it falls inside the libc executable
mapping. A function-symbol pointer must be interpreted alongside ELF/linking
information and `/proc/self/maps`; it is not automatically a libc base address.
The [legacy report](BASELINE-RESULTS.md) records its mapping samples in detail.

## Lab 02: calling convention and debugger evidence

The legacy program reports its three argument addresses at EBP+8, EBP+12 and
EBP+16 in run 1. EBP equals `__builtin_frame_address(0)`. No legacy debugger
transcript was captured.

In the separate modern GDB run, at the `inspect_frame` breakpoint:

```text
RDI = 1, RSI = 2, RDX = 3
RBP = 0x7ffe4c278440
saved RIP slot = 0x7ffe4c278448  (RBP + 8)
saved RIP value = 0x562a62fc32fc
```

The register values show the argument values at this breakpoint. GDB's `info
frame`, memory dump and backtrace agree on the saved return address. Source-level
addresses printed for modern argument variables refer to their storage in the
compiled function; they do not by themselves establish how arguments arrived.

The exact command and full transcript are in the
[modern session snapshot](evidence/modern-session-2026-10-27.json). GDB used
`set disable-randomization off`, leaving randomization enabled. This debugger
run is distinct from the three standalone executions; their addresses must not
be combined into one stack layout.

## Lab 03: compiler defaults and ELF requests

| Property | Legacy | Modern |
|---|---|---|
| Default / hardened ELF type | `EXEC` / `EXEC` | `DYN` / `DYN` |
| Default / hardened `main` | stable / stable | moving / moving |
| No-PIE ELF type | `EXEC` | `EXEC` |
| No-PIE `main` in all three runs | `0x80484db` | `0x4011ac` |
| Hardened imports `__stack_chk_fail` | yes | yes |
| Hardened `GNU_RELRO` and `BIND_NOW` | present | present |
| Hardened `GNU_STACK` request | `RW` | `RW` |

The modern no-PIE contrast stays fixed while the default PIE program moves,
within the same modern environment and ASLR setting. The hardened target enables
several protections together, so differences between default and hardened builds
cannot be attributed to one protection in this lab.

ELF indicators are evidence of binary properties, not proof of runtime guard
coverage or memory-permission enforcement. In particular, the selected legacy
CPU does not advertise NX. The modern CPU advertises it, but these labs contain
no execution-permission experiment. Neither side establishes an NX bypass or
successful exploitation. [Lab 04](../labs/04-stack-canary/README.md) separately
tests runtime stack-guard detection versus bounds checking.

## Reproduce and export

Run inside each VM as an ordinary user with the repository available:

```bash
# In the legacy VM:
bash scripts/capture-baseline.sh legacy /tmp/legacy-baseline
# In the modern VM:
bash scripts/capture-baseline.sh modern /tmp/modern-baseline
```

Copy both complete capture directories to the review machine, keeping their
internal paths intact. For the preserved local captures in this checkout:

```bash
python3 scripts/export-baseline.py \
  tmp/legacy-review/extracted-results/captures/legacy-baseline \
  tmp/baseline-comparison-20261027/extracted-results/captures/modern-baseline \
  --output /tmp/baseline-comparison.json
```

Use fresh output paths. The exporter verifies the root and each lab manifest,
requires exact artifact coverage, rejects symlinks and unsafe manifest paths,
and refuses existing output files. It validates every capture before creating
the JSON. When exporting multiple captures, it rejects differences in collector,
source, Makefiles or recorded build variables. Labels remain operator-supplied;
the exporter does not identify VMs or authenticate who ran them.

The modern run used a disposable overlay, read-only project ISO and separate
results disk, with `-net none`. No package installation or host hardening change
was required. Results were unmounted before normal guest shutdown and extracted
using read-only `debugfs` requests. All baseline manifests passed after extraction;
the original modern disk hash was identical before and after the session.
The modern snapshot records the launch command, CPU flags, package manifest,
user identity, boot command line, debugger command and supplemental file hashes.

Full binaries, disassembly and serial logs remain in the ignored local captures;
a fresh clone includes selected text evidence. Hashes establish consistency,
not authenticity. The legacy installation was recovered, and neither VM setup
is fully pinned for bit-identical reinstallation. A clean legacy installer run,
native legacy Lab 04 replication and execution-permission testing remain open.
